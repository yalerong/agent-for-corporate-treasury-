# 企业资金智能体 (Corporate Treasury Agent)

一个**会自己获取数据、自己总结规律**的资金管理智能体：把付款流水喂给它，它自动提炼出发薪日、固定付款、部门预算偏差等业务规律，产出**预算执行差异分析、滚动资金预测、外汇交易管控建议、关联方合规视图**四份决策材料。

核心设计哲学一句话：**LLM 总结规律，代码执行规律**——报告里每一个数字都来自确定性引擎，可追溯、可重放；LLM 的推理能力只用在规律提炼和例外判断上。

系统从 245 笔原始付款流水中**自动学到**了这些（无任何人工标注）：

```text
[high] ADP Payroll/USD     :: 月度固定付款, 约每月15日, 均额 118,670（7笔/7月）   ← 发薪日
[high] Landlord Ltd/USD    :: 月度固定付款, 约每月5日,  均额 18,000（7笔/7月）    ← 房租
[high] 深圳子公司(关联方)   :: 月度固定付款, 约每月10日, 均额 151,880（7笔/7月）  ← 关联方节奏
[prov] IRAS/SGD            :: 月度固定付款, 约每月20日, 均额 88,226（3笔/3月）    ← 季度税期
[prov] HK Co/运营/USD      :: 周度付款基准 23,035（31周样本, CV=0.54）           ← 日常水平
```

然后据此生成下月预测、逐条标注固定付款日提醒、给出不超预算额度的购汇区间建议。

## 快速开始（纯本地，无需任何 API Key）

```bash
pip install pandas numpy openpyxl PyYAML tabulate
cd cashflow
python make_sample.py   # 生成合成付款数据+预算（或把真实导出放进 data/raw/）
python ingest.py        # 标准化入库 SQLite（幂等，带来源与哈希）
python patterns.py      # 学习环：提炼规律 → patterns/patterns.yaml
python engine.py        # 行动环：月报+预测 → runs/<date>/report.md
```

接入真实数据只需两步：复制 `column_map.example.yaml` 为 `column_map.yaml` 改成你的导出列名；把 xlsx/csv 丢进 `data/raw/`。

## 架构：三个自主环

```
定时唤起(cron) ─┐                ┌─ 对话入口（app/ LangGraph 智能体）
                ▼                ▼
┌──────────────────────────────────────────────┐
│              Treasury Agent                   │
│   日常巡检 / 周期规划 / 复盘学习 / 例外处置     │
└──────┬────────────────┬──────────────────────┘
       │ 工具调用         │ 读写（变更须人工批准）
┌──────▼────────┐  ┌────▼─────────────────────┐
│ 确定性引擎      │  │ 规律库 Pattern Store      │
│ engine.py      │  │ 每条规律带证据链+置信度     │
│ 差异/预测/管控  │  │ provisional 不参与计算     │
└──────┬────────┘  └──────────────────────────┘
┌──────▼───────────────────────────────────────┐
│ 数据层  ingest.py → SQLite（来源文件+行哈希）   │
└──────────────────────────────────────────────┘
```

**感知环**（自己获取信息）：付款/预算导出标准化入库，幂等可重跑；余额 API 直连与定时巡检在路线图中。

**学习环**（自己总结规律）：`patterns.py` 每次复盘从全量历史重新提炼三类规律——周度付款基准（缺失周补零，防稀疏高估）、固定节奏付款（自动识别发薪/房租/税期/关联方，并从周度基线中剔除防重复计数）、月内集中付款日。每条规律带样本量、变异系数、置信度：

- `provisional`（样本不足或波动大）→ 只在报告中提示，**不进任何计算**
- `high` → 可进引擎，但须人工把 `approved: false` 改为 `true` 才生效
- 人工批准状态在规律重算时保留；每份报告钉规律库版本时间戳，审计可重放

**行动环**（分级自主权）：L0 观察报告 → L1 生成提案人工批 → L2 人批后执行到审批门。**付款执行永远不给 Agent 工具——安全靠工具不存在，不靠 Prompt。**

## 四份决策材料（engine.py 输出）

| 输出 | 回答的问题 | 机制 |
| --- | --- | --- |
| 预算执行差异 | 本月哪里超支/结余，根因是谁 | 预算 vs 实际逐组对比，差异>10% 自动定位 Top 收款方 |
| 滚动资金预测 | 未来 4 周每个主体/币种要付多少 | 周度基准 + 固定付款日逐笔排期，双轨不重复计数 |
| 外汇交易管控 | 该换多少汇、什么期限 | 预测净流出定区间，**上限钉预算额度**，期限匹配付款周期，风险中性不做方向判断 |
| 关联方合规 | 关联方资金往来是否透明可追溯 | 名单匹配逐笔追溯 + 近月趋势，异常节奏可见 |

## 对话智能体（app/）

LangGraph 多智能体框架：意图分类路由、双轨知识库 RAG（行业法规 + 企业制度，Qdrant + bge 本地 embedding）、HITL 人工确认节点、审计日志与敏感信息脱敏工具、Gradio 本地 UI。详见 [DESIGN.md](DESIGN.md)。

## 安全与合规红线

- 真实数据、账户映射、规律库全部 gitignore，仓库只含代码与合成示例（`*.example` 模板模式）
- 敏感字段进 LLM 前脱敏（`app/tools/masking.py`），Agent 只见内部代号
- 数值一律 Tool 精算，禁止 LLM 心算；法规引用必须带条款来源
- 规律进入计算的唯一通道是人工批准；预测连续恶化自动回退规律版本（路线图）
