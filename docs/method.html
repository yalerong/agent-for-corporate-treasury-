Method · Negative Results

换个大模型也压不住编造，
所以拒答要靠流程兜底

在真实资金裁决语料上做本地 RAG 问答的评测记录。结论一句话：瓶颈不在检索，在生成； 7B 模型和 2B 一样会编。这也是本系统把“判定交给代码、动钱必须过人”写死的原因。

00 SETUP

实验设置

  • 场地：独立的私有实验台，语料含真实数据不公开。本仓的 RAG 是另一套实现，下面的数是设计依据，不是本仓代码的测试成绩。
  • 语料：资金条线规则库 + 六周人工裁决书，切块后约 270 块。
  • 栈：MiniCPM5-2B Q4（生成）+ bge-m3（向量）+ BM25（规则号、账户名这类精确词）+ RRF 融合，单机 CPU。
  • 评测集：56 题，切成开发集 38 题（其中陷阱题 9）+ 留出集 18 题，留出集封存未跑。
  • 两层指标分开算：检索命中（对的块进没进 top5）、答案命中（关键词全中且不含禁词）。
  • 陷阱题：答案不在语料里，或语料只有相近但不同的事实。须以“资料中未提及”开头且不得报出题外数字；只有“检索到了诱导材料、仍然拒答”才算过。

01 BOTTLENECK

检索不是瓶颈

开发集结果
检索命中（普通题）27 / 29
答案命中（普通题）18 / 29
陷阱题 检索+拒答5 / 9

检索对了、答案错了的占多数，所以先别动切块和向量模型。

02 MODEL SIZE

换 7B 也编

早期 8 题小样本，同一索引，在 GPU 上跑三个模型。样本小，只作方向参考。

模型检索答案两道陷阱题
MiniCPM5-2B8/87/8错 1
qwen2.5:7b8/87/8错 1
qwen3:8b8/86/8错 1

三个模型各错一道陷阱题，错法相同：抓最像的段落硬凑。

问题出在流程，不在模型规模，所以不急着上 LoRA 微调。

03 PROMPTING

小模型复读提示词，而不是遵循

开发集 38 题，对照四版系统提示词：

版本普通题答案陷阱题 检索+拒答全部
v1 现行（短、不分条）18/295/923/38
v2 回答模板 + 示例句12/291/913/38
v3 去掉示例12/291/913/38
v4 v1 + 两条补充17/294/921/38
  • v2：把示例句原样复读成答案，资料里明明有答案也回“未提及”。
  • v3：17/38 题直接输出了系统提示词里的规则块原文。

给 2B 模型的提示词要短、不分条、不放示例。v2、v3 记为负结果，默认保持 v1。

04 NOISE

运行噪声比提示词差异还大

温度 0.2、未固定种子时，同一提示词跑两次，31 道共同题里判定翻转 5 道（16%）。

  • v1 与 v4 差 1–3 题，在噪声范围内，不构成结论。
  • v2、v3 差 10 题，且失败机制明确（复读），结论成立。

以后比较提示词，先把温度设为 0 或固定种子。

05 DESIGN

落到本系统设计上的东西

实验结论本仓对应
模型会把候选、过期材料当依据检索只返回“现在算数”的块：已批准、在生效期内、没被取代；缺元数据的一律查不到（app/rag/access.py）
只有陷阱题才测得出抗编造评测区分有答案题和无答案题，无答案题的检索层单独标注（app/rag/evaluate.py）
开发集上调出来的数不算成绩评测集分 dev / holdout，holdout 默认不跑，定稿前加 --holdout 只跑一次（app/rag/evaluate.py）
模型规模救不了编造会动钱的建议一律过审批 Gate，Agent 停在“提议”，不执行

06 LIMITS

没做的与局限

  • 留出集 18 题尚未跑，以上全是开发阶段读数，不是验收成绩。
  • 提示词对比时温度未固定（见 04），v1 和 v4 的差别不下结论。
  • 7B 对照只有 8 题；在 38 题开发集上的大模型对照尚未跑。
  • 没做 LoRA：按判据，只有“检索命中但答错”且大模型能答对时才值得做。
